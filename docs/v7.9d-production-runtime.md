# V7.9-D — Production Runtime

## Purpose

V7.9-D turns the composed executive into an explicit operational process boundary without moving execution authority away from V6.

## Runtime responsibilities

- **Lifecycle:** CREATED → STARTING → READY/DEGRADED → STOPPING → STOPPED.
- **Readiness:** dependency checks happen before the executive service starts.
- **Liveness:** a READY or DEGRADED process is live; FAILED and STOPPED are not.
- **Singleton ownership:** a runtime lease prevents two executive owners from starting concurrently.
- **Graceful shutdown:** stop the persistent service before releasing ownership.
- **Recovery:** after a clean stop, the same runtime can start again; the persistent executive service remains the downstream boundary for durable checkpoint recovery.
- **Failure isolation:** failed dependencies prevent service startup rather than allowing partial execution.

## Safety properties

1. The runtime never executes a workflow directly.
2. The runtime never grants autonomy or bypasses approval policy.
3. The runtime lease controls process ownership, not workflow authorization.
4. DEGRADED is explicit operational state, not hidden failure.
5. Dependency failure prevents the service from starting.
6. Restart re-enters the existing persistent executive service instead of creating a second execution authority.

## Production integration boundary

`InMemoryExecutiveRuntimeLease` is intentionally limited to tests and single-process deployments. A production deployment should inject a durable lease implementation (for example, a database-backed or distributed lease with expiry/fencing semantics).

The existing `PersistentExecutiveService` remains responsible for scheduling the composed executive loop. Its loop/checkpoint dependencies remain explicitly injected by the V7.8 composition root.

V6 remains the execution authority underneath the executive stack.
