# V7.9-E — Real-World Integration Boundary

## Purpose

V7.9-E defines the controlled boundary between Luuku's executive system and external services. The boundary is an adapter contract, not a second execution engine.

## Boundary

```text
External Action
      ↓
Integration Boundary
      ↓
Action / Capability Check
      ↓
Credential Boundary
      ↓
Input Validation
      ↓
Approval Enforcement
      ↓
Rate / Concurrency Control
      ↓
External Adapter
      ↓
Output Validation
      ↓
Audit Evidence / Trace Identity
      ↓
V6 Execution Authority
```

## Guarantees

- Unknown actions are denied.
- A capability mismatch is denied.
- Founder approval is required for actions explicitly marked as approval-gated.
- Missing credentials are denied and classified as authentication failures.
- Invalid input never reaches an external adapter.
- Concurrent execution of the same action is bounded by an injected concurrency gate.
- External adapter failures are classified without silently retrying them here.
- Adapter output must pass validation before it is returned.
- Every boundary decision creates an audit record.
- Trace IDs are preserved as audit evidence when supplied.
- The boundary never executes Luuku workflows and does not bypass V6.

## Deliberate Scope

This stage does not connect to production credentials or third-party APIs. `ExternalActionAdapter` is the integration seam where production adapters can later be introduced behind the same controls.

The in-memory registry, audit store and concurrency gate exist for deterministic tests and demos. Production implementations can replace those dependencies without changing the boundary contract.
