## Canonical Decision Path

The consolidation target is:

```text
Wake
 -> Observe
 -> Assess objectives
 -> Rank/select objective
 -> Score urgency/progress
 -> Assess intervention
 -> Read learning
 -> Adapt strategy
 -> Check strategic dependencies/conflicts
 -> Check capacity
 -> Build intent
 -> Build plan
 -> Apply autonomy policy
 -> Apply governance/approval
 -> Submit to V6
 -> V6 executes
 -> Observe execution truth
 -> Record outcome in memory
 -> Next cycle
```

The exact ordering of strategy, strategic dependency/conflict checks, and capacity is an implementation decision to be validated by deterministic integration tests. This document does not claim those standalone modules are already fully wired together.

## What We Must Not Do

- Do not create another objective-ranking engine.
- Do not create another execution engine.
- Do not let Lex call provider APIs directly.
- Do not make approval perform the action.
- Do not treat an in-memory default as production durability.
- Do not add another memory feature before defining retention/consolidation behavior.
- Do not declare production readiness from isolated demos.

## Consolidation Deliverables

### C1 — Canonical architecture contract

Define ownership, lifecycle, state boundaries, decision hierarchy, and invariants.  
**Status: complete in this branch.**

### C2 — Canonical composition

Create one production-oriented composition boundary that wires the executive dependencies explicitly without moving execution authority out of V6.

### C3 — Decision-path integration

Wire strategic dependencies/conflicts and capacity into the actual executive decision path where required, with deterministic tests.

### C4 — Durable production composition

Ensure objective, memory, checkpoint, event, workflow, and queue stores are explicitly composed as durable implementations.

### C5 — Consolidation verification

Build one end-to-end architecture demo/test that proves the complete decision path and all boundary invariants.

## Exit Criteria

V7.8 consolidation is complete when:

- one canonical executive composition exists;
- each decision has a defined owner;
- strategic and capacity signals have explicit integration points;
- durable stores are explicit in production composition;
- V6 remains the only execution authority;
- the full lifecycle can be traced deterministically;
- consolidation tests prove the architecture rather than only individual modules.

After this point, V7.9 can focus on **trust: observability, evaluation, safety, and production readiness** rather than adding more isolated executive capabilities.
